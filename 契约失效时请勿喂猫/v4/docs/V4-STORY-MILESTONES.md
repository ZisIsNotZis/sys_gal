# V4 剧情设计与逐日里程碑（3/16 → 3/27）

本文件是 v4 的**剧情设计 SSOT**：由 v1 故事大纲
（`v1/reports/full-story-arc.md`，2026-03-16 07:00 → 3/27 社区集市 21:30，
十个 VN 场景）适配 v4 班底（3 MC + 7 NPC）而来。逐日里程碑可量化、可用
`scripts/check_milestones.py runs/<artifact>.json --day N` 验证。里程碑是
**下限不是剧本**；检查器是纯函数（事件/发言模式匹配），模式细节随每日种子
落定而修订（修订记录在 git 历史）。

## 1. 总览

- **总天数**：3/16（周一）→ 3/27（周六）共 12 个模拟日 + 3/28 可选尾声，
  与大纲一致。外部截止线是 3/27 社区集市；中途公共节点是 **3/22（周日）
  3·16 台风纪念活动**（v4 种子已排程，对应大纲 Scene 7 的公开对质场景）。
  若模拟成本过高，3/23–26 的"并行筹备"日可用日程宏压缩——但其中的筹备
  失败→修复转折点必须保留（大纲 Scene 8 要求）。
- **目标结局**（大纲 T-A"成功但有代价"的 v4 化）：档案室记录缺失事件按
  正式渠道了结（有人承担、有书面结论）；台账与导出件的 22:05/23:30 差异
  及缺失目击行得到解释或立案；2013 年洪水路线的原始依据回流无障碍方案；
  陈默把当年那句完整的话当面说出，林瑶自主决定是否给出一次不带任务的
  见面；唐小岚决定草稿的命运（交还失主，或作为报道线索走正式核实）。
  台账系统案在所有被接受的条件彼此确认后，只给予**有界的客观澄清**——
  绝不给好感、运气或剧情豁免。
- **有效替代终局**（沿用大纲 §6 的精神）：
  T-B 诚实失败（集市/活动因硬约束取消，证据与责任留痕）；
  T-C 制度破裂（有人选择掩盖且被证据坐实）；
  T-D 个人退出（陈默拒绝台账案，世界自行走到终局）。
- **核心问题句**：*人们能否把承诺说清楚到可以相互依靠，而不把每段关系
  都变成法律文书？*（v4 化：说"我来"的人，这次要么做到，要么提前认。）

## 3. 逐日剧情段与里程碑

每天 = 大纲场景的一段；"需补种子"= 当前 manifest 未排程、需要新增的
当日排程/概念。里程碑项与 `scripts/check_milestones.py` 的
`MILESTONES[N]` 一一对应（新模式待当日种子落定后加入脚本）。

### 第 1 天（3/16 周一）：S1+S2+S3 — 发现、程序、档案室碰撞
种子已完整排程，实际运行 10/10 通过（校准基线，见现有 d1-* 十项）。
关键节拍：台账案开场（07:00）；登记本缺失与全员取证程序；台账 22:05 vs
导出件 23:30 差异被两位 MC 记录；档案室共处；老周托话；纪念活动通知。

### 第 2 天（3/17 周二）：S4a — 正式答复与"体面的版本"
- d2-书面说明提交：三份个人说明按期交给辅导员（"情况说明"+"提交"）
- d2-管理员答复：辅导员或教务方出现关于登记本/值班表的正式答复（"登记"+"答复/确认"）
- d2-台账案谈判：陈默与台账系统案交互（追问范围/期限；"台账"相关发言）
- d2-妈妈打听回流：陈默妈的打听结果回到陈默（需补种子：妈妈当日排程）
- d2-辅导员压力线：辅导员提出核查期限（"期限/截止"）
需补种子：管理员一方的一方一句话正式答复（通知/字条/短信皆可）；妈妈的当日事件。

### 第 3 天（3/18 周三）：S4b — 披露的代价
- d3-林瑶抄件压力：林瑶提及或交出"台账私人抄件"（软线：她自己开口才算）

### 第 5 天（3/20 周五）：S6 — 老家属院地下室与 2013 重建

### 第 6 天（3/21 周六）：S7 前夜 — 陈述与程序准备

### 第 8 天（3/23 周一）：S8a — 并行筹备

需补种子：结算场景排程；3/28 尾声（可选）。

## 4. 保守原则（不变）

- **信息不完整**（大纲 §3）：林瑶不知道差异的真相来源；何倩式报道线不
  得提前断言欺诈；陈默的童年真相**不得**由台账系统揭示——只能由人说出。
- **NPC 恋爱 deflection**（V4-CAST §4）：NPC 自带不可攻设定，自然转移。
- **extras 零记忆**：销毁即失，不承担跨日线索。
- **台账只给有界客观澄清**：不创造动机、不揭示任意秘密、不修复失败计划。
- **系统健康门槛逐日检查**（不计入里程碑退出码）：0 提供商 HTTP 错误、
  0 `[[` 泄漏、首次调用提交延迟 ≤2 分钟、每次 stranger_asked 同日出现
  extra_arrived。
