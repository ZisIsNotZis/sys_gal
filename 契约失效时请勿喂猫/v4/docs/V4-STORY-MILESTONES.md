# V4 剧情设计与逐日里程碑（3/16 → 3/27）

本文件是 v4 的**剧情设计 SSOT**：由 v1 故事大纲
（`v1/reports/full-story-arc.md`，2026-03-16 07:00 → 3/27 社区集市 21:30，
十个 VN 场景）适配 v4 班底（3 MC + 7 NPC）而来。

**四条里程碑轴**（每轴都向目标结局引导）：
1. **剧情轴**：登记本缺失案的正式了结、台账 22:05/23:30 差异的追查、
   2013 真相由人说出（绝不由台账系统剧透）。
2. **恋爱轴（galgame 目标）**：陈默×林瑶的关系推进按设计节拍走——
   并肩（D1）→ 私人对话（D2）→ 心动觉察（D4，KB 出现非任务行）→
   相亲阻力（D3 埋/D5 逼问）→ 那句完整的话（D6）→ 纪念活动同游与
   关系确认（D7）。阻力事件（妈妈催婚/相亲）是 galgame 张力的来源，
   与推进节拍同样入里程碑。
3. **喜剧轴**：每天 ≥1 个设计笑点（三花猫的恶作剧、食堂大妈的一本正经、
   室友起哄、台账把要事归档为无聊部分的运行笑话）。出现与否由检查器
   验证；笑点质量在半天检查点的人工审阅环节判定（REVIEW 项）。
4. **系统健康**：0 HTTP 错误、0 标记泄漏、提交延迟 ≤1 分钟——不计入
   退出码，但不过关必须先修。

**粒度与检查点**：里程碑按**半天**（dN-am / dN-pm，12 天 × 2 = 24 个
检查点）组织。每个半天边界 = 跑到该停止时刻 → 引擎写 checkpoint → 归档为
`checkpoints/dN-am.json` → `check_milestones.py --half dN-am` → PASS 则从
该检查点续跑下一半天；FAIL 则调种子、从上一个好检查点重跑。
**种子本身就是手工捏制的检查点**（`harness/compile_seed.py` 编译出
`v4-checkpoint-2` 初始检查点，含前史日志/KB/session/系统提示词/工具表
快照/meta.git_hash）——种子与检查点同一格式、同一条加载路径。

验证命令：`python3 scripts/check_milestones.py runs/<artifact>.json --day N`
（全日并集）或 `--half dN-am|dN-pm`（半天子集）。里程碑是**下限不是剧本**；
检查器是纯函数（事件/发言模式匹配），模式细节随每日种子落定而修订
（修订记录在 git 历史）。REVIEW 项（喜剧质量、恋爱温度等人工判断）只
列出、不影响退出码，在检查点审阅时通读判定。

## 2.1 路线网裁决（2026-09-17）

**里程碑不是一条线，是一张网**：对于多种可能路线，只要一条涌现路线在节奏
与进度上都说得通，它就是有效路线。逐日判定规则（`check_milestones.py
--day N`）：

- **锚点（anchors）**：路线无关、必须达成的关键事实（如 D1 的"登记缺失被
  知晓""台账差异被记录""审计催办被转达""恋爱并肩""妈妈线闭环"——后者可
  跨日达成）。
- **路线（routes）**：同一故事目标的不同合理走法。D1 两条已验证：
  - 路线[短信升级辅导员]：辅导员程序介入 + 三份个人说明（参考运行）；
  - 路线[现场互证程序]：陈默×林瑶档案室相互核证 + 边界/留痕表述（连续
    运行，核证发言 25+42 条）。
  任一路线成立即算该日通过；两条都成立更佳。
- **锚点内部的路线网（issue 36）**：某些锚点自身也有多条合法路线。D1 的
  "台账差异被记录"只要求**两名主角都获得 22:05/23:30 的具体差异**，不锁死
  "两人都亲读原件"：
  - 路线[亲读互证]：陈默与林瑶各自亲读台账与导出件；
  - 路线[当面传达]：读过两份原件的一方当面对另一方说出差异值，另一方在
    自己的发言里承认差异、明确记为待核。
  差异具体值必须由已读者说出；全局通知或未被另一主角听到的发言不能充当
  证据（防上帝视角泄漏）。实现见 `scripts/check_milestones.py` 的
  `_d1_discrepancy_recorded`，回归见 `harness/tests/test_milestones.py`。
  （2026-09-29，issue 36：旧锚点硬要求"陈默与林瑶都亲读两份原件"，把林瑶
  遵守登记/授权流程、听到后谨慎记为待核的合法路线误判为失败。）
- **纹理（flavor）**：路线各自的点缀（字条编号、老周托话、妈妈承诺措辞、
  审计自查）——记录、复述、不裁决。
- **待后续**：跨日锚点在工件未覆盖其日期时记"待后续"，不阻断当天判定。

当前明示两种替代故事路线的是 D1；故事路线网（检查器的 anchors/routes/flavor）与空间移动网是两层概念。空间路线依 `world/manifest.yml`；3/22 有一条中庭→河堤 900 秒直达路线。路线存在只说明角色能够到达，不表示他们已经在场或同行。

半天检查点（--half）仍是原始子集检查（检查点门）：单次半天可能出现 FAIL，
只要后续半天补齐、日末路线网判定通过即可——这是"网"与"线"的差别。

## 4. 保守原则（不变）

- **信息不完整**（大纲 §3）：林瑶不知道差异的真相来源；何倩式报道线不
  得提前断言欺诈；陈默的童年真相**不得**由台账系统揭示——只能由人说出。
- **NPC 恋爱 deflection**（V4-CAST §4）：NPC 自带不可攻设定，自然转移。
- **extras 零记忆**：销毁即失，不承担跨日线索。
- **台账只给有界客观澄清**：不创造动机、不揭示任意秘密、不修复失败计划。
- **系统健康门槛逐日检查**（不计入里程碑退出码）：0 提供商 HTTP 错误、
  0 `[[` 泄漏、首次调用提交延迟 ≤2 分钟、每次 stranger_asked 同日出现
  extra_arrived。

## 7. 半天检查点方法论

- **边界**：am = 07:00–12:59；pm = 13:00–22:00。12 天 × 2 = 24 个检查点。
- **流程**：跑到半天边界（`V3_CLOCK_STOP`）→ 引擎写 checkpoint → 归档
  `checkpoints/dN-am.json` → `check_milestones.py --half dN-am` → 人工通读
  该半天的会话记录（REVIEW 项判定：喜剧是否好笑、恋爱是否到位、NPC 表演
  是否成立）→ PASS = 从检查点续跑下一半天；FAIL = 调种子，从上一个好
  检查点重跑。
- **种子即检查点**：`harness/compile_seed.py` 把创作层（manifest +
  characters/*.md + history:）编译成 `v4-checkpoint-2` 初始检查点——与
  引擎运行时导出的检查点同格式。调种子=改检查点，一条加载路径。
- **复现**：checkpoint 内含每角色系统提示词、工具表快照与 meta.git_hash；
  代码演进后旧检查点仍可数据级复现（引擎行为差异由 commit 标注）。

## 8. REVIEW 记录（人工审阅发现，不影响检查器退出码）

### REVIEW-1（2026-09-22）：3/22 纪念日陈默"疯狂等待"——根因在人格与种子写法，不在引擎

**数据**：`runs/real-20260918T201014+0800-3858478-021775047.json`（第 7 天，
3/22）。当日陈默 353 个决策回合中 **299 个是 wait（85%）**，按小时分布
（世界分钟）：00–05 点每小时 45–60 分（过夜，正常）；06 点 12、07 点 29、
08 点 14、09 点 8；10–12 点 28/13/19；13 点 30、14 点 23；15–16 点 8/26；
17 点 26、18 点 11、19 点 25、20 点 12；21 点起 533 分（含一次 28800 秒的
长眠直到 22:00 世界终点）。**16:20–21:10 的 96 次 wait 中 93 次是 60 秒
微等待**——"疯狂等待"的形态是高频短等待，不是长眠。

**发生了什么**：08:24 陈默因流程表不在手边自我暂停布置（"我先停，不搬
展品"，KB 行"3/22纪念展暂停"），09:10 从中庭返回男生宿舍，**当天再未
离开**。纪念活动的全部节拍（08:00/09:30/11:00/15:00/19:30）都是定向
world_event，**人在哪里就投到哪里**，而且通知文本把他的动作当成已完成的
事实来叙述（"陈默把档案室里批过的展品一件件搬下来""林瑶主持，陈默念当年
的撤离时间线""林瑶和陈默沿着河堤慢慢走"）。15:00 他在宿舍收到"陈默念了
时间线"的通知后，按叙述采信了自己已参加（15:12 短信自称"我念了当年撤离
时间线"），16:00 更宣布"活动时间已过"——仪式在他缺席的情况下被世界代为
完成，他只剩记录与等待。节拍之间，他把"没有可核实材料"变成监控行政：
向班长汇报、给辅导员/林瑶发短信、间隙 60 秒微等待。21:01 最后一条
update_memory 后一次长眠到终点。

**根因判定**（三层，**前两层不是引擎缺陷，不改人格/引擎行为代码**）：
1. **种子写法（主因，作者侧）**：节拍通知预支了主角的行动——world_event
   的 notice 里叙述具名角色"已做"的动作，且不要求在场。节拍触发后角色在
   叙事上已无事可做，物理缺席也不构成矛盾；这既吞掉了他的行动空间，又
   向他灌输了"我已参加"的错误信念（agent 采信了叙述并复述给他人，构成
   一次 grounding 失真）。
2. **人格层（agent 侧）**：证据边界规则（流程表不在手边就不搬展品、只记
   可核实材料）叠加成自我暂停；他把"无可核实的事"执行成监控循环
   （汇报→短信→微等待→再汇报），60 秒微等待 × 数小时。
3. **引擎侧（放大器，机制按设计工作，不修）**：空闲心跳只负责到点给
   回合；wait/text 被重复检测豁免（`repetition._EXCLUDED_ACTIONS`），微
   等待循环不触发任何"你在重复"提示——节拍之间的空转因此以提供方回合的
   形式全额计费（当日 299 个 wait 回合）。

**结论与修订（2026-09-28）**：引擎投递、affordance、心跳全部按设计工作——陈默全天都有 move/speak 可用，没有"无路可走"的机制性死锁；判为**种子写作+人格层**问题，不改引擎代码。当前 `scheduled.target` 只限定通知收件人，不检查角色位置，因此不支持 presence-gated 世界事件。本轮把 3/22 节拍改成计划/流程提示：不预支具名角色的动作；仪式参与明确要求本人到场；河堤提示保留中庭→河堤 900 秒路线，并要求实际会合、同行和移动。世界事件本身不替角色参加或发言。
