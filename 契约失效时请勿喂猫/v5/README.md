# v5 — 重写的世界模型

v5 不是 v4 的续集，是同一实验室的**重造**：引擎只保留十条原始项，世界由库里的概念表达，故事只是使用它们的一份种子。规格在 `docs/`，代码在 `engine/` 与 `library/`，故事在 `stories/`。

## 现在能跑什么

M1 已交付：引擎骨架（实体、状态、包含、时间、事件、感知投递、心智、意愿、规则、命名解析）+ 《末班车》三条脚本路径。

```bash
cd 契约失效时请勿喂猫/v5

# 结构检查（状态键与渲染成对、引擎不含故事名词、孤儿概念、脚本只用库动词）
python3 scripts/v5_lint.py

# 引擎与故事的全部测试（含三条反向门与重放）
python3 -m unittest discover -s tests -p 'test_*.py'

# 跑三条路径，写出可通读的轨迹
python3 -m stories.s1_last_bus.run a b c
cat stories/s1_last_bus/runs/a.md
```

## 三条反向门（M1 的验收）

1. **摸与读不留痕**：读只写进读者的记忆，被读的纸一点都不变。
2. **渲染没有来源**：轨迹里不出现作者、写于、读者；纸只带着它上面写的字。
3. **指称不到时可行动**：说一个不存在的地方，得到"眼前能看见什么"，而不是一句"找不到"。

另有第四条：**轨迹只叙述有人感知到的事**，世界事件必须写明"谁感到"。

## 目录

```text
v5/
├── docs/       # 原始集、三层、场景清单、路线图（真理）
├── engine/     # 十条原始项；不认识任何故事名词
├── library/    # 概念：物性 + 规则 + 渲染 + 失败；按需增长
├── stories/    # 每支故事：seed.yml + 演员/脚本 + 验收 + runs/
├── scripts/    # v5_lint.py
└── tests/      # 引擎、门禁、重放、故事验收
```

## 生长的纪律

- 概念进库只有两条路：**被两支以上故事用到**，或**一次消掉一整类绕路**；否则留在种子层做局部覆盖。M1 只有一支故事，所以 `v5_lint.py` 把孤儿检查记为"待补"，M2 起用 `--strict` 变成失败。
- 下沉细节要付四件套：失败的场景、规则、渲染、测试。
- 引擎里出现故事名词、提示里出现状态键、种子里出现逻辑，都算越界。

## 与 v4 的关系

v4 仍是可跑的主线；v5 的 M2 通过后，v4 归档为参考。两边共用的运行纪律（唯一工件、检查点、重放、运行后分析）见仓库根的 `AGENTS.md` 与 `v5/docs/V5-ROADMAP.md`。
