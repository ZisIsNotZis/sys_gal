# 一日两个世界：《夜班》与《婚礼》的同尺度对照

这份文件是「一日两个世界」（M5）的第四件东西，也是 M5 里唯一要人读的一件。
它不宣布两个世界写得好，它回答一个可核的问题：**同一套概念在这两个世界里是不是都真的成立，成立在哪几处，哪里没成立。**

## 一句话

两个世界在量和形状上已经是同一个尺度（63/59/60/64 对 53/50/52/50 个做成的事，八条路最长空档都是 120 分钟），
七件共同的事（数、看、走、放、读、说、拿）在两个世界里都真的发生过；
**但同一件"在登记本上落一行"的事，两个世界用的是两个动词**（《婚礼》的 `sign`、《夜班》的 `shift`），
这是一处成立得不彻底的地方，条件与代价写在最后一节。

## 量：同一个尺度

| | 《夜班》 | 《婚礼》 |
| --- | --- | --- |
| 一局的时间 | 22:00 → 次日 08:05（10 小时 5 分） | 09:00 → 22:00（13 小时） |
| 地点 / 在场的人 / 物件 | 4 / 6 / 17 | 5 / 11 / 13 |
| 做成的事（a/b/c/d） | 53 / 50 / 52 / 50 | 63 / 59 / 60 / 64 |
| 失败的动作 | 0 / 0 / 0 / 0 | 0 / 0 / 0 / 0 |
| 最长空档（八条路） | 120 分钟（01:30 → 03:30） | 120 分钟（19:30 → 21:30） |
| 制度与物理的排程 | 6 件：补货到点、巡夜签到、清运车、清晨补货、收拾、白班开门 | 8 件：备餐、撤席、张贴两回、备餐登记、收拾两回、关厅锁门 |
| 出现在动作里的角色 | 5（接班者一人做了 34–40 件） | 10（酒店经理一人做了 19–22 件） |

两边的形状一样：**一整天由一个人扛住大半**——《夜班》是接班者，《婚礼》是酒店经理。
这不是替身，是这两个世界的制度本身长这样：值夜班的是一个人，办婚礼的是酒店的人。
但它意味着"十人同场"在《婚礼》里是**在场**成立、**参与**不成立：十一个人里九个动了手，多数只动了三五下。

## 成立在哪七处

| 那件事 | 《夜班》里长什么样 | 《婚礼》里长什么样 |
| --- | --- | --- |
| 数量是份数，不是形容词 | 抽屉数出 800、账上写 1000；后仓备用金 200；夜间补货数出 6 箱入账 | 新娘手里数出 8 个红包；晚宴的菜 10 份真的被端进厅 |
| 盘点由份数算出 | `library/stocktake.py` 一份读数一个出口；改 800 为 650 读数变 650 | 同一个读数入口（`count` 动词共用） |
| 隔着一层说话 | `打电话`：店长在电话那端，"我过不去"；两头互相看不见 | `当众说` / `私下说` / `转述`：厅内都听得见，隔一间屋子传不过去 |
| 期限到点自己回来 | 22:04 答应的顶班，次日 07:40 回到接班者面前 | 12:00 的午宴安排张贴、22:00 关厅锁门 |
| 制度角色替世界做事 | 巡夜签到、清运车、清晨补货，都不是谁的决定 | 备餐登记、撤席、送客车辆，酒店到点做 |
| 离场的人不在场 | 交班者走向店外之后不再出现在任何感知里 | 伴郎去停车场之后，厅里的话他听不见 |
| 不认识的人只能靠样子 | —（《夜班》没有生面孔） | `喊住`：只能按"穿灰夹克的男人"叫，名字与 id 都叫不动 |

前六处是两边都有的，第七处只有《婚礼》有——一条一行，不硬凑。

## 没成立的三处

**一、同一件事有两个动词。** "在登记本上落一行"在《婚礼》是 `sign`（签到本），在《夜班》是 `shift`（交接记录 + 交钥匙）。
两边的规则是同一条（本子得 `records: true`、手里得有笔、笔的墨得留得下），但 `shift` 把"落一行"和"交出钥匙"焊成了一个动词，
它的落行代码与 `sign` 是两份。这是 SSOT 上的一处重复，不是功能缺陷：交接在制度上确实是一个动作。
**会推翻这个判断的条件**：第三个世界需要"落一行 + 交出一样东西"而那不是交接班——那时 `shift` 必须拆成 `sign` + `give`，而不是再焊一个词。

**二、"十人同场"只在场、不参与。** 十一个人里十个动过手，但酒店经理 19–22 件、伴郎 11–12 件，其余多数 1–3 件。
《婚礼》的"记忆互污"因此只由两条证据撑着（谁读过那一行 1–2 人、伴郎当众说了一句"早上我看见一个穿灰夹克的男人从门口过来"），
不是十个人各说一套。S5 场景清单里要的"同场十人的记忆互污"，这一局只做到了两个人的。

**三、《夜班》的店长只有一句话。** 每一条路两次打电话，店长说一句"我过不去，钥匙在谁手里，这一班的账就记在谁头上"，然后不再出现。
远程通道这个能力成立了，但"一个人在电话那头持续施压"这件事没有被这局演出来。这是密度问题，不是判据违反。

## 证据怎么复核

在 `契约失效时请勿喂猫/v5` 下：

```text
python3 -m unittest discover -s tests -p 'test_*.py'   # 208 支，含 M5 的四条判据
python3 scripts/v5_lint.py --strict
python3 scripts/anti_cheat.py --verbose                 # 两支故事各四条路四个不同结局
python3 scripts/pack_trajectory.py check                # 25 件工件与原始逐件一致
python3 -m stories.s4_night_shop.run && python3 -m stories.s5_wedding.run
```

通读的入口是 `stories/s4_night_shop/runs/<路>.md` 与 `stories/s5_wedding/runs/<路>.md`；
每个动作的完整上下文（他知道什么、看见了什么、原始工具调用）在同一个目录的 `<路>.context.md` 里。
