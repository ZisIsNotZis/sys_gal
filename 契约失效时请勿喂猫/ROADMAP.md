# ROADMAP — 项目里程碑与工作包

本文件是**项目交付计划 SSOT**：把最终目标拆成有序的、面向用户同步与验收的
里程碑（Milestone），以及每个里程碑下的工作包（Work Package）。

> **区分两种里程碑**（不可混称）：
> - **剧情里程碑**（story milestone）：半天/逐日的剧情锚点，由
>   `v4/scripts/check_milestones.py` 判定，权威是 `v4/docs/V4-STORY-MILESTONES.md`。
> - **项目里程碑**（delivery milestone，本文件）：一个可独立判断的交付垂直切片，
>   是用户同步与验收点。
>
> 本计划是**提案**：里程碑列表须经用户确认后才能进入自动执行模式。
> 上次更新：2026-10-13（Eager 整理）。

## 0. 最终目标与方法论（回指 SSOT）

- **最终目标**：一个可复现的**叙事实验室**——自主角色依据自身动机与合法获知
  的信息行动，世界按显式规则运行，轨迹可检查、可回放；据此产出一条因果连续
  的 12 日中文校园故事，走向目标结局 T-A。
  （`README.md`, `docs/PRINCIPLE.md`, `v4/docs/V4-STORY-MILESTONES.md` §1）
- **方法论**：
  1. **种子即检查点**：作者设计种子（编译为初始检查点），世界运行它；作者可在
     两次重跑之间改种子，**不得静默修补正在跑的一局**。
  2. **五层分离**：客观世界 / 感知 / 信念 / 记忆 / 公开记录
     （`docs/PRINCIPLE.md` §3）。
  3. **半天检查点环**：跑到边界 → 存档检查点 → 过剧情锚点门 → 人工审阅 →
     PASS 从检查点续跑 / FAIL 调种子、从上一个好检查点重跑。
  4. **预门**：任何大型 provider 运行前，历史失败回归 + 确定性终点门 + 种子
     自洽门必须全绿（`AGENTS.md`）。
  5. **运行后分析**：每次 provider 运行后必须人工检查轨迹，以具体行为与因果
     问题报告，不得用计数/标签代替结论（`AGENTS.md`）。
  6. **证据与独立复核**：验收绑定到工件/修订；自动执行模式下每个工作包默认
     需要独立复核。
