# 59 — update_memory 的键语义摩擦：24 次/上午，是当前最大错误类

Status: ready-for-agent
Need-review: yes
Need-test-cases: yes

## 观测（2026-10-01 完整重跑）
52 个错误回合中 **24 个是 update_memory**（最大类）。典型：
- 把标签塞进时间键：`!at=3/16(周一) 08:10 上午班`、`!at=3/16(一) 12:05 中午回来` → "unparseable scheduled key"；
- 复合键当新行：`!always 签名人 老街坊代表`、`!always 林瑶行程`、`!contact 林瑶 桂姨` → "no row keyed"；
- 对不存在的键用 `op=edit`（唐小岚 4 次、陈默/林瑶/宿管阿姨各若干），每次下一回合改 `op=open` 补救。

## 根因
键是"行的句柄"且必须逐字匹配，而模型的自然写法是"时间/指令 + 标签"或"多词复合键"。错误信息正确且可自纠，
**但上午因此浪费约 24 个回合**，且多键批量里一错整批回滚，丢掉同批的有效记忆。

## 验收方向
1. **宽进**：`!at=M/D(周X) HH:MM <标签>` 应被接受（标签自动成为第二个键），而不是报错；
   复合键在多键 edit 时能命中"全部键都在同一行"的行（或给出"你想要的可能是 X"的**单步可执行**建议）。
2. **部分成功**：一批 rows 中某一行失败时，其余行应照常写入并在结果里分别报告（现在整批回滚会丢信息）。
3. **指标**：检查器把 update_memory 失败数单列（便于观察趋势）。
4. 回归（先红后绿）：上面三类真实写法 → 修后不再报错或给出单步可执行的纠正；既有正确写法语义不变。
