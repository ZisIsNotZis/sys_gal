# 63 — 同种动作连续失败不触发停滞提示；"上菜/递物"没有动词

Status: fixed
Need-review: yes

## 观测（2026-10-01 对照跑 `real-20261001T121425+0800-223688-090345540`）
41 个错误回合中 13 个是"read/take 不可得"，其中两类很典型：

1. **同类失败不触发停滞**（`尼龙绳`×4）：同一件事换了四个说法继续撞墙——
   `尼龙绳` / `一卷尼龙绳` / `捆货用的绳子` / `值班室的粗尼龙绳`，全被拒。
   停滞/重复监测按**完全相同的 (kind,args)** 计数，参数一变就不算重复，于是没有任何提示。
2. **"上菜/递物"动词缺口**（食堂大妈×4）：`take 一碗豆浆、一个菜包、一个豆沙包`、`take 荤菜、素菜、米饭、一碗汤`、
   `take 一套包子豆浆（两个包子一碗豆浆）`——她是在**给窗口上菜**，而世界只有 `take`（拿起）与 `give`（递给自己拿着的东西），
   没有"服务/交付本就在手边的食物"的表达，模型只好去 take 不存在的东西。
3. 另有两例 `read 教学楼正门内侧公告栏` / `read 公告栏底下的过期通知`——公告栏是**地点级可读物**，
   不是已注册文档；拒绝文案已列出"你现在能读的"，但仍属"世界描述里像是存在、实际不可读"的残留面。

## 验收方向
1. **同种动作连续失败计入停滞**：同一 `kind` 连续被拒 N 次（N 可配，默认可取 3）即触发一次停滞提示，
   提示里列出"此处确实有的东西/确实能读的东西/可用的替代动作"。参数不同也计入（这正是本次漏掉的情形）。
   注意别把"正常的多目标尝试"误判（例如连续 3 次 `text` 给不同人属正常）——只计**被拒**的动作，并要求同 kind。
2. **服务/递物**：给出最小可行方案并说明边界——例如允许 `give` 的目标是**当前地点的物品**（先 take 再 give 的语义不变，
   只是当物品就在手边时给出可执行路径），或在提示词/错误文案里明确"上菜=先 take 再 give 给客人"。
   不得放宽 `give` 的所有权语义到"凭空给别人不存在的东西"。
3. **公告栏类地点级可读物**：二选一——注册为可读实体（有 content）或明确写成不可读；
   无论哪种，拒绝文案必须给出**可执行的下一步**（去哪里/问谁/能读什么）。
4. **回归（先红后绿）**：
   (a) 同一 kind 连续 3 次被拒（参数不同）→ 产生停滞提示（**今天必红**）；
   (b) 正常的多目标 `text`/`speak` 不误触发；
   (c) "上菜"场景给出可执行路径（先 take 再 give，或明确的替代动作）；
   (d) 公告栏类 read 拒绝含可执行下一步。
