# 41 — 排程通知缺受众字段即全局广播：场景内对话被整城听见

Status: ready-for-agent
Need-review: yes
Need-test-cases: yes

## 复现与证据

manifest 81 条排程通知中 **25 条没有 `target`**；缺省即投给全体角色（`kernel.py:280`
附近，history/notice 投递的 visible_to 缺省为全部 actors）。多数是真正的公共事实
（上课铃、开饭、下雨、world_stops），但其中至少两条是**场景内视角文本**：

- `counselor_office_opens`（10:30）"[[辅导员办公室]]的会开完了，门打开；现在可以从
  [[教学楼]]走廊进去。"
- `application_rejected`（12:30）"[[学生会办公室]]值班干事把话说明白了：本周的场地申请
  一律不受理……"

对照：`accessibility_check` 写了 `target: 林瑶`。

后果（可证）：唐小岚整上午独坐半坡咖啡馆（nearby 常为空），却在 turn 168/184/276
把这两条当亲历见闻说出并转告林瑶（"学生会办公室值班干事把话说明白了""辅导员办公室
的会开完了"）。她并非推测，而是被世界直接告知了别人房间里的对话——**信息边界由投递
缺省值决定，而不是由剧情需要决定**。

## 根因

通知的受众不是一个显式契约：不写就广播，而 notice 文本又常常写成"某人当面说了X"的
视角句。写通知的人无从知道"不写 target = 全城播报"，lint 也不检查。这与已修复的
追悼通知问题（issue 27 系列）同族，但那次是 presence-gating，这次是**缺省值本身**。

## 验收方向

1. 排程通知必须有显式受众：`audience: world | location:<name> | actor:<name>`；
   lint 缺字段即红（25 条一次性清账）。
2. 视角语境句（含"把话说明白了/门打开/我看见/听见"等视角线索）不得声明 `world` 受众；
   要么限定地点/角色，要么改写为客观事实句。
3. 回归（先红后绿）：一条带视角句且无受众的通知 → lint 红；限定 `location:` 后，
   不在该地点的角色事件流里不得出现该 notice（用最小 run 或注入测试断言 visible_to）。
4. 顺带记录：`lunch_rush` 这类"整个楼层都知道"的句子是合法全局通知，改造时不要误伤。
