## 1. E1（P0）· `leave_note` 的 `on: ""` 被当成"声明了要写进文书"

**证据（全天 106 条拒绝片段 / 99 个回合，6 个角色）**

```text
08:06 陈默 leave_note {"text": "3月16日 08:06，陈默核对记录：…", "persist": true, "on": ""}
拒绝：leave_note: leave_note 的 on（写进既有文书）与 persist（留一份新文稿）只能选一个。
      Valid call: {"name": "leave_note", "arguments": {"text": "…"}}
```

- 分布：陈默 60（08:06→17:19）、林瑶 23（08:43→12:53）、林瑶室友 8、下棋大爷 3、唐小岚 3、辅导员 2。
- **叙事后果**：陈默 11:25 对林瑶说"我之前三次尝试留书面说明都没有成功，实际没有写下或提交"；16:43 在面核记录上写"我未成功写成并署名自己的书面说明"；直到窗口结束他的《个人情况说明》仍不存在（全天的 `document_annotated` 里没有他的说明，只有 16:48 的面核记录批注）。林瑶/林瑶室友/下棋大爷 08:43–09:03 的中庭观察稿同样报废十几次。
- 机制位置：`harness/kernel.py:1727-1733`

```python
on = intention.args.get("on")
if on is not None:
    if intention.args.get("persist"):
        raise ActionRejected("leave_note 的 on（写进既有文书）与 persist（留一份新文稿）只能选一个。", …)
```

  `""` 满足 `on is not None`，于是"留一份新文稿"被自己判成冲突。
- 建议：`if on not in (None, "")`（并在 `action_schema` 说明里写"要留新文稿就别写 on，也不要写空的 on"）。守卫测试：`on:"" + persist:true` 必须成功产生 `note_left`。

## 2. E2（P0）· `move` 的 `with: [""]` 被当成"有同行者"，且世界没有"独自走"的表达

**证据（全天 76 条空名字；移动类拒绝片段合计 159 条）**

```text
08:27 唐小岚 move {"target": "学生会办公室", "with": [""]}
拒绝：move: move 的 with 里有一个空名字。 Valid call: {"name": "move", "arguments": {"target": "中庭"}}
08:29 / 08:43 / 08:45 / 08:47 / 08:54 / 08:58 / 08:59 同一形状重复
```

- 分布：唐小岚 15、林瑶 19、陈默 17、班长 10、辅导员 5、林瑶室友 5、下棋大爷 4、宿管阿姨 1。
- 相邻失败形态说明模型确实在找"独自"的表达：`with: ["唐小岚"]`（自己）→ "unknown name '唐小岚'"；`with: ["_self"]` → "unknown name '_self'"；`with: ["陈默"]` → "unverified partial name '陈默'"；`with: ["陈默(you)"]` → "unknown name '陈默(you)'"（17:45–17:49 陈默三连）。
- **世界级后果（这是本窗口最贵的部分）**：
  - 13:04 唐小岚对外说"我现在发现移动需要明确同行者"，随后 13:19–15:08 花 88 分钟逐人求同行（林瑶室友/宋大爷/李大姐/林瑶/陌生人/陈默），15:06 才遇到张学长；
  - 17:51 陈默给宿管阿姨发短信"刚才几次想回男生宿舍都没走成"，17:58 靠辅导员同行才走成；
  - 12:10 陈默把引擎拒绝复述给林瑶："刚才系统提示你正在往别处走，所以没法带你同行"——**引擎措辞进入角色口语**，故事层被接口文案污染。
- 建议：① `_canonicalize_companions` 先 `strip()` 并丢弃空项，过滤后为空即"无同行"；② `action_schema` 的 `move` 说明加一句"独自走就不要写 with"；③ 拒绝回执对空名字直接给一句"要去就只写 target"的更正（现有 `Valid call` 实测未能纠正，见 76 连）。守卫测试：`with:[""]` ≡ 无 `with`。

## 3. E3（P1）· 同分钟两人 `take` 同一单件，都成功，只有一个真拿到

**证据**

```text
17:56 辅导员 take 一份晚饭   → 无错（action_started 17:57）
17:57 陈默   take 一份晚饭   → 无错（action_started 17:57）
结束态：陈默 inventory ['2013年邻里撤离通知书','一份晚饭','便签本','可用纸笔','空白纸']；
        辅导员 inventory ['场地申请表']；item_locations 已无「一份晚饭」
17:58 辅导员对外说"谢谢，我们都拿了晚饭。"
```

- 结果：一条既成事实的"两人都吃到饭"与背包状态矛盾；辅导员被系统悄悄骗了一次（与 E1 同族：**回执说成功，世界没变**）。
- **复现结论（票 98 §3）**：不是"item 被重复发放"，也不是"第二人失败而回执错报"，而是**第二人通过了校验、拿到成功回执、日志也照写一条 `action_completed take`，但世界没动**——`take` 的归属只在完成时写进世界，同一 tick 的两次提交都看到它还在桌上（陈默 #4707 先提交先后完成 #4718，辅导员 #4708/#4719 是空转）。已在提交期修掉：第二次结构化拒绝并点名占用者，`give` 的就地递出同族同修。
- 建议：`take` 的校验与提交在同一世界版本复核（票 75 的族未清）；第二个 take 必须被拒并说明"已经被 X 拿走"。

**证据**：15:01 唐小岚读过 `代话便条`（内容："稿子的事我晓得了，让他们别再往吧台上放；要是他们问起，就说我改天自己过去一趟"）；15:05 她朝"陌生人"说话求同行，15:06 回话者是 **张学长**（无 `extra_arrived` 记录）：


- 一个路边陌生人把她还没送到的托话内容逐字说了出来。故事后果：15:44 她到糕点铺再"当面送到"同一句，16:47–17:12 她向胡大叔解释"我后来当面更正并送到了"——**送达这件事被提前兑付了一次**。

- 建议：陌生人/extras 的生成上下文只给"问句 + 现场公开可见物 + 自己身份"，剥离问话者的 `memory`、`document_read` 正文与 `notes`，也剥离 `known_to` 限定给别人的物件描述。
