# 66 — 联系人与路线死路：李阿姨不可达、老周通讯录不对称、305宿舍不存在

Status: fixed
Need-review: yes
Need-test-cases: yes

## 观测（2026-10-01 对照跑，多名 reviewer 分别报出）
1. **李阿姨结构性不可达**（陈默妈主线目标之一）：`knock 李阿姨家` → "不是一个你知道的地方"；
   `text 李阿姨` → unknown name；`move 老家属院` → "没有可用的路"。原因是 `李阿姨` 在 manifest 里只是
   `kind: generic` 概念（无地点、无电话），而陈默家/老家属院都是 `remote:true` 仅电话可达。
   于是"给李阿姨带话"这个目标**永远不可能完成**，也无人纠正。
2. **通讯录不对称**：宿管阿姨能给"老周"（下棋大爷）发短信，但**下棋大爷的通讯录里没有她**——
   他回信报 `text: unknown name '下棋大爷'`（宿管阿姨侧）→ 借绳线成死胡同。
3. **305宿舍不存在**：林瑶室友 `move 305宿舍` → "不是一个你知道的地方"（她自己的寝室未建模，只能停在"女生宿舍"节点）。

## 验收方向
1. **可达性契约**：任何被角色当作目标/联系人使用的具名对象，必须要么可到达、要么可联系、要么**明确不可用并给出替代**
   （现成的"unknown name"文案已给候选，但缺"该怎么办"的路径）。
2. **通讯录对称性**：若 A 能给 B 发消息，则 B 的可用联系人里应包含 A（或明确说明为何单向，例如 B 没有手机）。
   lint 或运行时校验给可见提示。
3. **地点粒度**：需要进入的具体房间（如 305宿舍）应注册为地点或明确不可进入（不要留一个"你知道却到不了"的名字）。
4. **回归（先红后绿）**：(a) 李阿姨这类目标给出可执行路径或明确不可用+替代（今天必红：现在三条路全死）；
   (b) 通讯录不对称能被检出并给出可见提示；(c) 305宿舍这类名字要么可达要么明确不可进。
   历史失败登记进 `test_historical_failures.py`。
