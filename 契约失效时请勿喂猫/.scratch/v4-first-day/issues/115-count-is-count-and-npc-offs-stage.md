## 0. 一句话

用户指出两处别扭，都成立：**“只剩最后一张时那张纸才变成那份说明”是把件数混进了
语义**；**“老周晚上没地方睡”是把舞台问题写成了角色问题**。

## 1. 件数就是件数

113 的写法是“余数 > 0 时那张纸仍是纸，余数到 0 时它才变成那份文稿”——后半句是错的
叙述：文稿从一开始就是作者手上另一样东西，纸从来没有“变成”过它。

修法：

- 字段改名 `sheets` → **`count`**（`World.item_counts`、payload 的 `count_left`）：
  一件东西里有几件，是纯数量，不带任何语义变化。
- 写完的回执改成两句之一：“这份书面记录写在「说明用纸」的一张上，现在在你手里
  （编号 …）。那沓还剩 11 张，别人拿去还能接着写。” / “那是这沓的最后一张——这沓纸
  用完了。”
- 代码注释、种子注释、`V4-ENGINE.md` §7.11、`V4-AGENT-INTERFACE.md` 的 leave_note 行
  同步改成“拿走一张”的说法，“变成文稿”这类叙述全部删除。
- 行为不变（写一张少一张、少到 0 时这件东西从世界上出账），只是叙述与命名不再暗示
  “数量决定它是什么”。

## 2. NPC 到点退场，不需要一张床

113 之前种子里有一行 `laozhou_night_shelter`：天黑、各处关门、回老家属院的大巴开走了，
“老周今晚得自己在校园里找一个能进、能待的地方”。结果：这个 68 岁的 NPC 整夜在校园
里找住处，235/323 条夜间发言都在这件事上，而世界根本没有“住处”这个机制，也没有一条
能让他闭场的路——一个开场就不收尾的紧急事故。

这是设计错误，不是角色问题：NPC 没有自由意志，他不需要住处；他需要的是**到点退场**。

修法：

- 去掉那条“求宿”的排程，换成收场：棋散了、棋子收进布袋、搭门口修车老相识的三轮回
  `老家属院`（远程地点＝台下），并说明“明天下午他还来”。
- 退场由排程把 npc 放到场外（`place_actor`，只对 npc 生效），不是靠台词解释。
- 3/17 15:30 补一条 `laozhou_back_on_stage` 把他放回中庭：退场是“这一场不在”，
  不是“这个人没了”，D5 的“大爷讲古”还等着他。
- 副作用（良性）：夜间不再有大批“他该睡哪儿”的发言，也就不会把夜间回合吃光。

## 3. 半日粒度与门禁读法（用户裁定，写进 ROADMAP M1）

- 一局只跑一个半天；到边界过门 → 人工复盘 → 满意才从它的检查点续下一段；不满意就改
  种子/引擎，从**上一个已知好的检查点**重跑。不带着问题往下跑，也不为省一次运行重跑整天。
- 半天门禁判的是“这一天的预期轨迹有没有发生”，不是对/错。FAIL 是**警告**：复盘要回答
  “对结局必要吗 / 还剩几条自然走到它的路 / 余量多少”，只有没余量时才动种子，且只补
  **机会**（共同在场的时机、走得通的路、点名到人的提醒），不写台词。
