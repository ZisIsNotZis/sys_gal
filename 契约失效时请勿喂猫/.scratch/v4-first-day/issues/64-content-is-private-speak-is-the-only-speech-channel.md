# 64 — 翻转默认值：正文=私下想法，`speak`/`text` 才是说话的唯一通道

Status: ready-for-agent
Need-review: yes
Need-test-cases: yes

## 证据（2026-10-01 对照跑 `real-20261001T121425+0800-223688-090345540`，已由我复核）

1. 该run 共 **265 条 `speech` 事件**：**96 条来自显式 `speak`/`text` 调用**，**169 条来自普通正文（content）**经
   T1「文本即说话」广播。
2. 来自正文的 169 条**绝大多数是旁白/计划**，本不该被听见，例如：
   - 陈默 07:00「台账的话还在耳边：…先把手里这张泛黄的通知书从头到尾看一遍…」
   - 陈默 07:02「先别急着开口——台账要的是…答错没有第二次。」
   - 陈默 07:25「到岗第一件事是签到，但台账在三问——先把台账本子本身翻开细读…」
   - 唐小岚 07:05「七点过了，店里还没人。我把磨豆机豆仓补满…然后擦好台面，等着开门…」
3. 更严重的实例（**3 名独立复盘者分别报出**，我已逐条核对：这些文本**没有对应的 speak 调用**，确系正文通道）：
   - 陈默 07:59「林瑶进来了。她常在这儿值班…登记本被拿走的事她可能知道。**当面问，比发短信快。**」`heard=['林瑶']`
   - 陈默 08:06「…**我必须先认账**：今早我压根没开过左手抽屉…**先把实话说了，再去核实。**」`heard=['林瑶']`
   - 辅导员 12:09 的私密判断被广播后，唐小岚 12:11 据此说出"她八点五十翻过审计包"——**跨角色污染**。
4. ticket 56 的护栏是**高精度窄集**（协议词 + 显式隐瞒誓言），普通"计划叙述"不命中，因此指标显示
   「仍被广播的私密正文: 0」**是覆盖不足，不是问题消失**。

## 裁决（用户授权范围内，我基于上述证据决定）
**翻转默认值**：普通正文（assistant content）是该角色的**私下想法**——记入其私人记录，**不广播**；
说话只能通过 `speak` / `text` 工具调用。理由：正文里 169/265 是旁白而非对白；模型本来就会用 `speak`
（96 条）；继续靠"猜哪些正文像台词"是打地鼠，且已经失手一次。

## 要做的事
1. **引擎**：取消"content 无条件 → 公开 speak"；正文改为记入该角色的私下记录（与 ticket 56 的
   `withheld_private` 机制合流，但**不再需要标记匹配**——默认就是私下）。`speak`/`text` 调用语义不变。
2. **提示词**：明确写清"正文是你的想法，谁听不见；要说话就用 speak（要私聊就用 text）"，
   与 `docs/V4-AGENT-INTERFACE.md` §1/§4 逐字一致（沿用逐字一致性测试）。
3. **过渡自纠**：若某回合**只有正文、没有任何 speak/text 调用**，且正文里含**引号对白或第二人称称呼**
   （"你/您/大爷/瑶姐…"这类明确是对人说的话），给一条自纠提示："这段没有说出口——正文只是你的想法；
   要说出口请用 speak。"（仅此一种高精度条件触发，避免噪音）
4. **指标**：检查器把"正文未说出口（含疑似对白）"计数单列；同时保留 ticket 56 的护栏作为 speak/text
   **参数**的第二道防线（不要删除）。
5. **回归（先红后绿）**：
   (a) 正文里的旁白/计划**不再产生任何 speech 事件**（用上面的真实文本做夹具，**今天必红**）；
   (b) `speak`/`text` 调用的文本仍照常送达（用同run的真实台词做绿例）；
   (c) "只有正文 + 疑似对白" → 产生一次自纠提示且**不广播**；
   (d) 既有 ticket 56 的护栏测试仍绿。
   历史失败登记进 `v4/harness/tests/test_historical_failures.py`（引用 169/265 与上方实例）。
