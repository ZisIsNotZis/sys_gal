# 61 — 未标 known_to 的已放置文档，其完整描述展开进所有角色的 KB

Status: ready-for-agent
Need-review: yes
Need-test-cases: yes

## 现象与证据（由 ticket 58 的排查定位，本条按"报告不顺手改"单独立档）

`world_loader._expand_entity_rows` 对**没有 `known_to`** 的实体一律展开给所有人（"公开可见层"）。对
`items` 无碍（当前都有 known_to），但**五份已放置的 `documents` 没有 known_to**，于是它们的**完整描述**
进了每个角色的 KB：

- `2013年邻里撤离通知书`、`2013年台风台账`、`2013年外借记录导出件`、`学生会审计包`、`校报草稿`。
- 实证：宿管阿姨/食堂大妈/辅导员/班长都带有一行
  `[2013年台风台账]: 档案室铁皮柜里的纸质台账…2013 年那一页有反复翻动的折痕`。
  **这正是宿管阿姨 i=196「那一页最近折痕翻得厉害——有人这阵子老去翻」的字面来源**——她全天没离开值班台，
  也没读过该台账。ticket 58 修掉的是"地点内部细节"（食堂大妈那句"铁皮柜按年份码着"），
  **没有**修掉这条文档描述泄露，所以 58 只解决了一半个案。

## 根因
描述（=`world/{documents,items}/*.md` 的正文）被当作"公开层"对所有角色展开；而它与 ticket 40/49/58 的语义
冲突：**知道有这么个东西** ≠ **知道它的内容与状态**。文档的内容/状态必须有来源（读到、被展示、被告知）。

## 验收方向
1. **规则统一**（与地点 brief/内部细节同构）：已放置的 document/item 的描述**只对 `known_to` 里列出的角色**
   展开；其余角色在**看到/读到**之后，经 ticket 49 的 `observed` + `[所见]` 机制获得客观描述。
2. 若作者希望某份文档"众所周知"，就显式写 `known_to`（而不是靠"没写 = 全公开"的缺省）。
3. **回归（先红后绿）**：
   (a) 未列在 `known_to` 且从未到过档案室的角色，其 KB/primer 不得出现台账的描述（用宿管阿姨做夹具，今天必红）；
   (b) 到达档案室后（ticket 49）必须能拿到该描述；
   (c) `known_to` 里列出的角色仍如常获得；
   (d) 既有 items 行为不变（它们已有 known_to）。
   历史失败登记进 `v4/harness/tests/test_historical_failures.py`（引用"折痕"证据）。
4. lint：若某已放置文档的正文提及具体状态（折痕/缺页/涂改等），而其 `known_to` 为空 → 提示"这等于全公开，
   确认是否有意"。不阻断，但要可见。
