# 46 — 感知快照与提交时校验不一致：同一回合说"在场"却判"不在场"，一个坏收件人作废整句

Status: ready-for-agent
Need-review: yes
Need-test-cases: yes

## 复现与证据（同一工件）

- **班长** i=212（11:09）：`speak` 对陈默被拒 `absent: 陈默`；而**同一回合的 affordances 明确写着**
  `{"kind":"speak","to":["下棋大爷","陈默","陌生人"]}`。
- **班长** i=215（11:14）：`speak` 报 `unknown name '下棋大爷'`，而该回合 `nearby_actors=[下棋大爷]`。
- **辅导员** T7（11:30，turn-227）：三人 speak 因 `unknown name '下棋大爷'` **整体被拒**，同一句里
  其他收件人的话一并作废；候选名单里反而列着当时不在场的唐小岚/宿管阿姨。
- **陈默** turn 145/147、**辅导员** T8/T9/T14/T16：`not executed: current … completes at …`
  同一根因重复 4–6 次（"一回合只应有一个耗时动作"没被说明）。

## 根因

感知/affordances 是**决策时的快照**，而链提交时按**已推进的世界**重新解析在线人员与名字；
两者不一致时，模型看到的"可选"恰好是提交时判为"不可选"的。加上：
(a) 名字解析与在场判定是**整批全有全无**——一个收件人出问题，整句作废；
(b) 失败信息里给出的候选来自另一次快照，可能出现不在场的人；
(c) 模型被提示"重试"却不可能成功（重试时机不掌握在它手里）。

## 验收方向

1. 判定依据回到**决策所见**：提交时的在场/名字校验以该回合感知为准；期间离开的人按
   "已离开，话没送到"的可恢复结果处理，而不是让整句消失。
2. **逐目标处理**：多收件人的 speak/给/交付按目标拆开，能送到的送到、送不到的单独报，
   不再一错全废。
3. 失败信息里的候选名单必须与该次判定同源，且**每个候选都确实可执行**（同 issue 39 的
   "建议必须能成功"）。
4. 提示词/接口明确"一回合一个耗时动作"，减少 `current … completes at` 这一类。
5. 回归（先红后绿）：感知含 A、提交时 A 已离开 → 断言其余收件人仍收到话，且结果为
   "对 A 未送达"的可恢复记录；断言 affordances 与提交判定由同一快照生成。
