## 1. P0 · 台账对话通道可寻址，但事实表不可猜；拒绝还不入日志

**证据（A）**：陈默第一回合就用 `to=["台账"]` 说话，共 5 次（07:00、07:02、07:04、09:08、09:10），全部 `submitted`——票 91 §1.1 的路由**成立**。但 `system_answer` 0 条、`system_reward_granted` 0 条。

| 原话 | 事实表键 | 命中 |
|---|---|---|
| 台账，关于我接下的案子，请告诉我：这案子是什么、责任人是谁、期限是什么？ | — | 否 |
| 台账，你案卷里记的关于《2013年邻里撤离通知书》的条目是什么？ | `2013年邻里撤离通知书的责任人是谁？` | 否 |
| 台账，你记着的《2013年台风台账》的借出记录是什么？ | — | 否 |
| 台账，你的案卷里关于借阅登记本缺失这件事，记载的期限是什么？ | `当前记录的期限是什么？` | 否 |
| 台账，你案卷里关于《2013年台风台账》…记载的经手责任人是谁？ | — | 否 |

`Ledger.query` 用 `self.facts.get(question.strip())` 逐字匹配；`pack.system["facts"]` 只有三条键：`红色哨子在哪里？ / 2013年邻里撤离通知书的责任人是谁？ / 当前记录的期限是什么？`（已实测 5 句 `exact-key? False`）。角色从 `system_case_accepted` 只拿到 `terms`（"说出它是什么/说出责任人是谁/说出期限"），拿不到条目原文，于是**每一次都只能"不知道"**；07:06 他的私有想法已经把它读成"台账不回应泛问"，09:10 后放弃，此后 8 小时 0 次。

**两个缺陷合一**：

1. **可答性**：`terms` 是抽象三条款，`facts` 是逐字的具体问句，两者之间没有任何桥（既没有"条目清单"可看，也没有归一化/关键词匹配）。**建议（不改语义的前提下）**：`Ledger` 在 `system_case_accepted` 的投递里带上"它只答这三条：<条目原文>"，或把表键改成 terms 的原话；同时把与本案无关的"红色哨子"条目移出或接上线索（种子侧 R1）。
2. **可审计性**：这 5 次拒绝**在世界日志里 0 痕迹**（引擎刻意不 `submit speech`），只写在 tool 回执里；陈默会话 13:32 被压缩后，回执全部丢失。复核者只能靠"没有 system_answer"反推"答不上"。**建议**：拒绝也提交一条私有事件（`system_answer` 带 `ok: false`，或新增 `system_query_refused`），`visible_to` 只含受约束角色，`_reconcile` 只数 `ok: true`，与票 93 的"结案 ≠ 首次命中"分组保持一致。

而 16:20 的 `面核记录` 正文要求："材料名称、经手人、当面提问与结果…谁到场核对，谁就往自己那一栏里填…缺什么记什么，不补写。"班长 16:31 到场、16:33 读到（"纸面还空着，一行字也没有"），只能在 16:42 用 `leave_note` 另贴一张说明，并明确写"我没有在面核记录上签称已核对"。**结果是面核记录 0 人签、0 行字。**

## 4. P0 · 没有"搀扶/陪行"原语，房号也不是地点：一个不可能的需求吃掉 6 小时 51 分

**证据（B/H）**：305 相关发言 **219 条 / 17 个角色 / 10:00–16:51**；"我不能/没法/做不到 + 扶/搀/陪/带/走"的拒绝 **165 条 / 16 个角色**；`stranger_asked` 43 条里 29 条是同一句求助。

## 5. P1 · extras `aliases` 的触发条件与派工语言不匹配
