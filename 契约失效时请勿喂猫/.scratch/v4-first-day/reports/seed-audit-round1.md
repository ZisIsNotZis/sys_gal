**2) "flavor 在 `--half` 被阻断"——机制与修订建议（设计建议，未实施）**

现状（读码确认）：
- `main()`：`checks = [c for c in MILESTONES[day] if half is None or c["half"] == half]`，随后 `if not ok: failed.append(...)`，最后 `return 0 if not failed else 1`（`check_milestones.py:1505-1512, 1590-1591`）。**`--half` 把这个半天的每一条检查都计入退出码。**
- 路线网判定被显式跳过：`# ---- 路线网判定（--day 模式；--half 是检查点门，不套用路线网）----`，`if half is None:`（`:1535-1537`）。

于是 `--half d1-pm` 的要求**严格大于** `--day 1`：
- 它要求 **5 条 flavor 全部 PASS**（`d1-字条留痕程序`、`d1-老周托话`、`d1-妈妈承诺`、`d1-纪念活动通知`、`d1-林瑶自查审计包`，`:948-853`），而 `--day` 明确不裁决它们；

修订建议（一段设计建议，交给判定层 owner）：
> 把"门禁强度"从"半天/全天"这种时间切法里解耦，写成检查项自己的属性。给每个 `_mk_check` 增加显式 `tier`：`anchor` / `route:<路线名>` / `flavor`，并让 `ROUTES[day]` 只按 id 引用同一张表（目前 `anchors`/`requires`/`flavor` 是手写的第二份清单，写错一个 id 时 `flavor_fails` 静默为空、`--day` 永远不报——已经是一处静默漂移点）。然后 `--half dN-pm` 的退出码只由 `tier == "anchor"` 且属于该半天的检查决定；`route`/`flavor` 项照常打印（标记 `[INFO]` 而不是 `[FAIL]`），并在输出末尾给出两行独立结论：`GATE: PASS|FAIL（anchor）` 与 `EXPECTED_LATER: <该半天仍缺的 route/flavor id>`。若希望半天检查点仍能给出与日末同口径的判断，替代方案是让 `--half` 用"截至窗口结束的事件"跑**日级路线网**（锚点 + 任一路线成立），即把 `if half is None:` 换成 `if half is None or <窗口覆盖到该半天结束>`，这样"单次半天 FAIL 可日末补齐"这条文档契约才在代码里成立。另外无论选哪种，`--half` 都应同步过滤 `turns`/`sessions`（或明确声明半天模式的回合类判据不可用），否则窗口语义在两套数据上悄悄不一致。
