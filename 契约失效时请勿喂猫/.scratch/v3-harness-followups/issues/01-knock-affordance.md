# Derive physical interactions from world structure

Status: done
Type: bug

The current renderer exposes `knock` as prose such as “knock at closed archive”, while the executable protocol treats it as a special global action. This is ambiguous for agents and would require a new kernel action kind for every ordinary verb.

Replace that narrow design with a generic physical-interaction seam. Important objects may be explicit world entities, but ordinary scenery and boundaries should be derived from location/object types. The engine should expose a generic interaction request such as `interact(target, verb, parameters)`, resolve the target against the actor's actual perception, and validate the verb against the target's physical capabilities. `knock` is the first regression case, not a permanent hardcoded action kind. Routine interactions remain programmatic; genuinely ambiguous multi-step intentions may still use the world interpreter.

## Agent Brief

**Category:** bug
**Summary:** Replace hardcoded ordinary verbs with a generic, world-defined physical interaction seam.

**Desired behavior:**
An agent can submit an interaction such as `interact(target="harbor-archive", verb="knock", parameters={})`. The harness resolves the target from the actor's legal perception and validates the requested verb against the target's derived physical capabilities. Ordinary scenery and boundaries do not require separate entity files unless they have unique identity or state.

**Acceptance criteria:**

- [ ] The protocol supports a generic `interact` request with target, verb, and parameters.
- [ ] A closed reachable boundary exposes and accepts `knock` through that generic request.
- [ ] The natural-language affordance and executable action shape agree.
- [ ] Visibility, reachability, boundary state, capability, and parameters are validated by the kernel.
- [ ] Open or unreachable targets cannot accept the same interaction.
- [ ] Adding another ordinary interaction does not require another top-level action kind.
- [ ] Regression tests cover rendering, successful submission, and rejection cases.
- [ ] No plot, romance, affection, relationship, or protagonist-specific behavior enters the engine.

**Out of scope:**

- Creating a separate world file for every door, chair, cup, or other ordinary scenery.
- Selecting the harbor archive's narrative role or access secrets.
- Replacing complex prose intentions with an exhaustive verb taxonomy.

## Acceptance criteria

- A closed location boundary can expose a natural-language interaction without requiring a separately authored door entity.
- The agent can submit a structured generic interaction targeting the perceived location/boundary and specifying `verb: knock`.
- The kernel validates target visibility, reachability, capability, and parameters, and emits a normal observable event on success.
- An open or unreachable boundary does not offer or accept the same interaction.
- A regression test proves that the renderer's wording and executable shape agree.
- Adding another ordinary world interaction does not require adding another top-level kernel action kind.

## Scope boundary

Do not model every piece of scenery as a Markdown file, and do not add affection, plot, or character-behavior logic to the engine. Preserve prose/GM escalation for actions whose consequences cannot be derived from seeded physical capabilities.
