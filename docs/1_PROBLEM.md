# PROBLEM — 为什么值得做这件事

## EXPLICIT

做的是一个**叙事实验室**：一个可复现的实验环境，其中自主角色依据自身动机与合法获知的信息行动，世界按显式规则运行，任何轨迹都可检查、回放。它不是成品游戏，也不宣称人类级的故事质量。

要研究的是"故事最后到底是谁写的"这个问题：一局是被世界推动的，还是被作者推动的。作者写下去的东西只能是世界的条件——地点、制度、班次、谁知道什么、门几点关；角色的动作必须是角色自己从它当时的信息里做出来的。

## INFERRED

由此产生的痛点是具体的、可枚举的，每一条都在这个仓库里出现过：

- **全知**：模型若拿到整份种子或别人的私密状态，它就不再是一个在场的人，而是一个读过剧本的演员。这是 v4 里"批注带作者""全局通知"的样子。
- **作者替角色做决定**：种子里写"让甲去交说明"、排程里写"命运让灯坏了"，故事一定读得通；读得通正是它危险的地方，因为读者分不出差别。
- **结局由剧本写死**：一支故事只写得出一条路，或几条路都汇到同一个结局，"结局"就是作者的断言，世界没有参与。
- **不可复核**：没有事件账本、没有逐回合上下文、没有可回放的记录时，"他当时知道什么"无法审计，于是任何结论都只是转述。
- **一天是假的**：时针跨了午夜而夜里没有人做事、下午九个小时空着，轨迹能证明"过夜了"，不能证明"过了一天"。
- **指标反过来塑造工件**：为让动作数追平而加失败动作、为让空档判据变绿而把事件堆在两端——判据绿了，事实没变。

## 为什么值得

这六条不是理论风险，是这个仓库里真实发生过的、被门放过去又被人工通读抓回来的东西。把它们各自变成一条可机械复核的判据、一条能写的故事、一次真实的运行，就是本项目的全部工作。
