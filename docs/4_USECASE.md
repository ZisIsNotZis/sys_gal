# USECASE — 谁在什么处境下把什么做完

四条完整的流程（用例），然后是七支故事作为价值切片（每条带它自己的验收）。

## 用例一：作者把一支新故事写成能跑的世界

处境：库里已经有前一支世界的概念，要换一个世界，证明这些概念不是焊死在那支故事上的。

1. 读 `4_USECASE.md` 的这条场景要求（这一支必须能表达什么）与 `5_PRODUCT.md` 的阶梯位置。
2. 写 `stories/<story>/seed.yml`：地点、卡司与知识、物件与份数、制度与班次、排程。种子里只写"世界是什么样"，不写"接下来发生什么"。
3. 写 `scenario.py` 的脚本路径：每条路证明一件事物理上做得到，尽头是这支故事自己的结局；结局由世界事实拼出，不从路径名或查表取。
4. 跑出 `runs/<路>.md`、`.json`、`.events.json`、`.context.md`。
5. 走门：全测试、`v5_lint --strict`、`anti_cheat --verbose`。
6. 逐条检查判据能被推翻：改世界里的一个数、拿掉一件排程、把两条路写成同一种走法，看该红的地方是不是真红。

失败的走法也写在案里：加失败动作凑数、把事件堆在两端凑"一整天"、给某个角色塞一条"让……去……"——三种都发生过，三种都被退回。

## 用例二：跑一次真模型运行，然后审读它

处境：脚本演员已经证明这件事做得到；现在要看模型自己会不会这样走。

1. 拿到一次授权（上限与模型写在授权里）。没有授权就不跑。
2. 预门全绿；预门红即阻断，不"先跑跑看"。
3. 跑，产出唯一的运行目录（绝不覆盖）。花费记进 `run.json → spend`，到上限即停。
4. 打包（`pack_trajectory.py pack`），`check` 绿。
5. 审读：先读代表回合（早、中、晚、失败边界）的轨迹，再读对应世界事件与该回合上下文；报告以具体行为与因果问题开头，不以计数或 clean/failed 标签结尾。协议在 `AGENTS.md`。
6. 把这一局暴露的缺陷写成根因 + 修在哪一层，落进 `8_DETAIL.md` 或下一包。

## 用例三：复核者判断一支包算不算交付

处境：执行者已经宣布完成，一个新的上下文进来，只看最终工件与证据。

1. 读该包的契约（提交信息里）与它的判据。
2. 自己跑判据命令，不看执行者的读数。
3. 读工件本身（轨迹头尾、测试断言、反向控制探针），找"绿但抓不住"的地方。
4. 出裁决：`pass`，或 `fail` 并指出是哪一条判据没有被真正证明。

## 用例四：人在里程碑边界做判断

处境：里程碑的四条判据都有了物证，但"这局像不像真的过了一天""这份对照值不值得当作判词"只有人能答。

1. 收到一份报告：结论先行，然后是每条判据的证据指向、然后是报告认为**没成立**的地方。
2. 读那件要人读的工件（对照报告、轨迹节选）。
3. 回答：接受 / 不接受并说明哪一处不够；开不开下一包。

## 价值切片：七支故事

每支都是一支独立工件（种子 + 卡司 + 验收 + 轨迹），永久留作回归夹具。表里的"必须能表达"就是它的验收。

| 故事 | 处境 | 必须能表达 | 都可行的结局 |
| --- | --- | --- | --- |
| 《末班车》 | 22:30 的末班车，三站路，一个人把包留在了座位上 | 共同在场与隔断（隔门说话要不要被听见）、封闭容器（打开前不可知）、离场（下车后不许被"轮询"）、到站时限、敲 | 不动、交给司机、打开、追上失主 |
| 《借条》 | 19:30 的出租屋，一张借条、一杯没动的水、三个人，只差一句"今晚"的压力 | 书写（钢笔擦不掉、铅笔能擦）、痕迹（添笔与涂改留下的样子）、辨认（这是谁的字）、复制（副本带不带来源痕迹）、在谁手里、在场见证 | 不改、改了没被发现、改了被认出、当场说破 |
| 《夜市》 | 18:00 的夜市，一摊货被收走，押金条在几个人手里传过 | 制度角色（谁有权收东西）、条子在多人手里传递、当众与私下的感知差、收摊与明早的期限、张贴、口头承诺到点把人叫醒 | 认账、推给下一个人、拿不回来、当众澄清 |
| 《夜班》 | 便利店的一个夜班，交接班盘点少了两百块，摄像头坏了 | 数量与盘点、交接（班次与交接记录）、锁与钥匙、远程通话（店长不在场）、公开记录（小票、班表）、代班承诺 | 找到了（记错）、真丢了、被人做了账、自己背 |
| 《婚礼》 | 酒店宴会厅的一整天，签到本上多了一个谁都不认识的名字 | 人群并发（十人同场而感知有限）、传闻扩散、记录的权威（签到本上写下的算数）、无名者靠衣着被指称、同场十人的记忆互污 | 查出是谁、没人再查、记录被改、大家装作没看见 |
| 《快递站》 | 三天里的一个丢件，三天里每个人都改过一次口供 | 跨日状态、记忆失真、记录与记忆的冲突、责任归属、信任 | 找到、赔了、责任落在最弱的人身上、没人再提 |
| 《契约失效时请勿喂猫》 | 12 天的校园，2013 年那份撤离通知书上的签字是所有人都在替别人保管的秘密 | 全部，加上关系与长时承诺 | 目标结局 T-A（档案室记录缺失案按正式渠道了结、台账差异被解释或立案、2013 真相由人说出、恋爱线有明确终局、草稿命运被决定） |

长弧另有一份"必须能表达的场景"清单（复印台账、替不在场的人签字、三份说明在期限前当面提交、借阅登记、门禁与钥匙、隔着门与电话、张贴通知、改约到明早八点、夜里有人退场、2013 年的通知书、三个人说法不同、记录被人动过、谁读过什么、关门后取物、请客分东西）。每条的去处与它的首次覆盖写在 `5_PRODUCT.md` 的覆盖矩阵里。
