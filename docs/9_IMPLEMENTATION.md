# IMPLEMENTATION — 环境、门、测试策略、跑与打包的规矩

## EXPLICIT — 跑之前必跑的门（在 `契约失效时请勿喂猫/v5` 下）

```text
python3 -m unittest discover -s tests -p 'test_*.py'
python3 scripts/v5_lint.py --strict
python3 scripts/anti_cheat.py --verbose
python3 scripts/pack_trajectory.py check
```

四条全绿才算这一棵树是可引用的。`v5_lint` 管结构（引用可解析、每个状态键有渲染、孤儿概念、引擎盲区、种子严格形状）；`anti_cheat` 管反作弊三检；`pack_trajectory check` 管轨迹是不是都在 git 里且还原得回去。预门不是"先跑跑看"的理由：红即阻断。

另有自己的一份历史失败台账 `tests/test_historical_failures.py`：每一条观察到的缺陷对应一个会变红的测试，编号 `R01…`，新的缺陷往后排。台账是这道门里最有价值的东西——它让"这个错我们已经犯过一次"成为可运行的断言。

## INFERRED — 测试策略

- **三层各自落地**：引擎（原始项、解析、编排、重放、检查点）用逐字节回放与反向夹具测；库（物性、规则、渲染、失败）一概念一测试，至少一条成功、一条失败、一条"别人看不见"；故事（种子、卡司、验收）测每条路可达、每条路的结局不同、以及这支故事最怕的那个错。
- **反向控制是判据的一部分**：判据必须能变红。已经这么做过的四处：结局唯一性（阈值退回常数即红）、同尺度空档（拿掉一件排程即红）、盘点（把数写死即红）、整日（拿掉一条路的空动作即红）。新增判据要同时给一个能推翻它的探针。
- **零花费的回归**：结构判据一律用 MockProvider 或脚本演员跑；花钱只发生在里程碑边界，且要有授权。
- **工件要与提交一致**：`runs/` 由 `python3 -m stories.<story>.run` 生成，重跑之后 `git status` 必须干净。

## EXPLICIT — 一次 provider 运行的纪律

1. 一次授权一局，上限写进授权；一局的花费记在它自己的 `run.json → spend`（授权、模型、上限、tokens、价钱），到上限即停，不许悄悄再跑一次。
2. 每次调用产出唯一的运行目录，绝不覆盖。
3. 跑完 `pack`，`check` 绿，再引用任何读数。
4. 跑完必须人工读轨迹：先读早、中、晚与失败边界处的代表回合，再读对应世界事件与该回合上下文；报告以具体行为与因果问题开头，不以计数或 clean/failed 结尾。协议在 `AGENTS.md`。
5. provider 不稳是常态：带退避的重试、失联有界放行；重试预算耗尽的失败是终局，存成失败轨迹。
6. 中断了不重来：从最后一个检查点续跑，事件号与版本连续，会话历史保留。

## INFERRED — 轨迹哪一件都不许丢

运行工件的契约（四件文件、打包形态、`check` 的四类失败）在 `docs/7_INTERFACE.md`；这里只说纪律：跑完先 `pack` 再 `check`，两者绿了才引用读数；打包件是入 git 的那一份，原始件留在本地。花钱跑出来的 provider 轨迹一条记录都不许丢，打包后要能 `unpack` 原样还原（逐件摘要一致）。

## INFERRED — 环境与约定

- Python 3（本机 3.12）；依赖只有 `PyYAML`；打包用 `zstd`。无虚拟环境的特殊约定，仓库直接跑。
- 目录即包名，用下划线：`stories/s4_night_shop/`。
- 引擎保持 story-neutral：`engine/` 的源码里不出现故事名词（lint 的盲区检查就是这一条）。
- 种子严格：未知字段即报错，不许静默丢弃。
- 凭证不进仓库：只写名字或占位符。
- 提交信息就是工作包的契约与决定；一次提交是一件原子事实。本地领先远端时也不推——推与不推由人决定。

## INFERRED — 一次"改文档"的规矩

文档按层用一个家（`docs/0_ROADMAP.md` 与 `docs/1…9`）：一个事实只写在一个文件里，别处指过去。文档写当前事实，不写日期叙事、不写 changelog、不写"曾经是 A 后改 B"；每条写清来源（人说的 / 人确认的 / 我推的）与把握程度。值得留但当下没时间落地的事实先追加到 `docs/0_STAGING.md`，整理时搬进该去的层。
