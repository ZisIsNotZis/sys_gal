# ARCHITECTURE — 子系统边界与质量属性策略

这里只写子系统归谁、为什么这么切、以及哪些约束决定"东西能写在哪"。模块内部的机制在 `docs/8_DETAIL.md`，跨层的形状与文件名在 `docs/7_INTERFACE.md`。

## EXPLICIT

### 三层：引擎、库、种子

| 层 | 拥有什么 | 不拥有什么 | 谁读它 | 改动成本 |
| --- | --- | --- | --- | --- |
| **引擎** `engine/` | 十条原始项；解析（指称→实体、话→意愿）；编排（时间、排程、回合、检查点）；重放；智能体表面与工具表的生成 | 任何故事名词、任何具体动词、任何物性 | 只有引擎自己 | 最高：引擎的破坏性变更要重证历史失败台账 |
| **库** `library/` | 可复用的常识：物性与规则、渲染、失败回执、制度效果、状态键渲染、盘点、动词登记 | 世界实例、剧情、任何故事名词 | 引擎加载它；模型通过它看见日常动词 | 中：一概念一条测试，进库要过两条判据 |
| **种子** `stories/<story>/` | 实例与地点、卡司与其知识、制度与班次、排程、例外、初始状态、本故事的验收 | 逻辑（任何 `if`/循环/计算）、引擎真相（谁写了什么、谁读过什么）、对具名角色的祈使句 | 作者与检查器 | 低：改一支故事不碰引擎与库 |

**为什么这么切**：一个事实只有一个家。引擎内部只有原始项；模型只看见由库生成的日常动词；种子只写这一部作品的具体事实。三种越界各自删掉一类错误：引擎里出现故事名词是耦合（引擎认识了某一部作品）；提示里出现状态键是泄漏（模型看见了世界真相）；种子里出现逻辑是失控（作者在运行前写好了接下来发生什么）。

这个切法还让"库不是焊死在一支故事上"成为可观测的验收面：同一套概念必须在第二个世界仍然成立；只在一个世界成立的概念是那个世界的方言，不是库概念。

**库概念是五件一套**：物性（要求对象具备什么）、规则（`when`/`do`/`cost`/`render`/`fail`）、渲染（参与者各自看到什么）、失败（回执与可行清单）、测试（至少一条成功、一条失败、一条"别人看不见"）；另带 `used_by`（哪几支故事用到，孤儿检查读它）。缺一件不算完成。

### 十条原始项作为架构骨架

| # | 名称 | 一句话 |
| --- | --- | --- |
| P1 | 实体 | 有稳定身份的东西，人也算 |
| P2 | 状态 | 实体上的结构化物理事实（键→值） |
| P3 | 包含 | 实体在某个容器或地点里，一棵树，无环 |
| P4 | 时间 | 单调时钟 + 到点触发 + 动作耗时 |
| P5 | 事件 | 不可变的状态变化记录，带因果 |
| P6 | 感知投递 | 一条事实经某个通道进入某个心智 |
| P7 | 心智 | 能积累感知、持有知识、提出意愿的实体 |
| P8 | 意愿 | 心智提出的一次改变尝试，合法性由规则裁 |
| P9 | 规则 | 从（意愿 + 物性 + 状态 + 时间）到原子效果的声明式映射 |
| P10 | 命名解析 | 心智如何指称实体：名字、别名、描述、指代、序数 |

十条是引擎的全部词汇。日常概念（写、读、说、拿放、走、复制、锁、吃、等与睡、承诺）都由它们组合而来，全部住在库里。新增第十一条要同时过三关：现有十条无法组合出它而不让每个使用者重复同一不变式；它是解析或编排层需要的，而不是某个世界的物理；它不携带任何故事含义。任一不过，它就是库概念。逐条含义与"不含什么"在 `docs/8_DETAIL.md`。

### 智能体表面：引擎生成，故事不许手写

一个角色每回合拿到的东西由引擎从世界状态投影出来，不由故事各写一份：

| 部件 | 内容 | 硬规则 |
| --- | --- | --- |
| 一眼 | 时间、所在、眼前有什么、手里有什么 | 只见物理：纸上"上面有字"，看不到内容 |
| 最近 | 他实际感知到的最近几条，逐字 | 只来自他自己收到的投递 |
| 知道的事 | 他相信的事（身份、常识、对人的看法） | 可能错、可能旧，世界不替他纠正 |
| 细看 | 把眼前的东西看到细节（怎么写的、有没有折痕） | 仍不给正文 |
| 读 | 取得正文 | 唯一得到内容的动作，且只进自己的记忆 |
| 检索、回想 | 在**自己**的记忆里按字面找 | 找不到就是找不到，没有语义猜测 |

两条硬规则：上下文只含他自己感知过或相信过的东西；每回合把这份上下文连同他的动作一起记进轨迹，否则"他当时知道什么"无法审计。系统提示与工具表也从种子的 `identity` 与库的动词表生成，故事里不许再写一份——同一件事两个家就会漂移。

这一层不新增原始项：它只是 P6（感知投递）与 P7（心智）的一个视图。

### 重放、检查点、打包在架构里的位置

- **重放**是引擎边界上的性质，不是一个外挂工具：所有状态变化都走 P9 的原子效果，每条事件记下应用后的世界摘要；重放 = 在初始世界上重演原子效果并逐事件比对摘要。对不上就抛 `ReplayMismatch`，不猜。
- **检查点**把"世界状态 + 到此刻为止的账本前缀"冻结成一份文件；续跑 = 还原两者，再让同一份脚本或演员往下走，新事件接在旧编号之后。所以"从种子整本重放"与"检查点续跑"必须是同一个世界——这就是续跑因果连续的定义。它属于引擎，格式见 `docs/8_DETAIL.md`。
- **打包**是证据策略：一次运行的四件原始材料是本地可读副本，事实的家是紧凑工件 `runs/<story>-<路>.jsonl.zst`，逐字节可还原、不裁剪内容。工件契约在 `docs/7_INTERFACE.md`，打包与核对的实现细节在 `docs/8_DETAIL.md`。

三件事共用同一条事实：事件账是世界唯一的账本。重放读它，检查点切它，打包把它连同视图一起带走；任何一件绕过账本，都会让另一件失效。

### 按需具体化：粗到细的阶梯

默认停在最粗的一级。只有当**某个故事的验收在不具体化的前提下无法成立**时，才下沉一级。以"写"为例：

| 级 | 表达 | 什么时候允许停在这里 |
| --- | --- | --- |
| 1 | 这东西能被写 | 任何故事都能写上去 |
| 2 | 钢笔写的擦不掉，铅笔写的能擦 | 某支故事的验收依赖可擦性 |
| 3 | 这支笔的墨遇水会化，那支不会 | 某场戏的验收依赖这个差别 |
| 4 | 在这个位置写会被看见，在那个位置不会 | 需要"当众/私下"的物理差异时 |

每次下沉的代价是四件一套：一个失败的场景（证明不具体化就过不了验收）、一条规则、一个渲染、一个测试。缺任何一件，下沉被拒绝。

### 进库判据：两条路径

一个概念可以进 `library/`，只有两条路：

1. **至少两支故事用到**（没有孤儿概念）；
2. **它一次消掉一整类绕路**（例如"复制"一次消掉"抄件只能由种子写死"）。

不满足的留在种子层做**局部覆盖**：声明式、lint 可见、带一句"为什么现在不上升"。第二次用到时再上升，不许提前上升。

## CONFIRMED

- **版本线的归属**只指到 `docs/adr/0002-v5-becomes-the-main-line.md`；本文件不复述那条决定的内容。
- **物权留在种子层**，不进库：P3 的包含关系已经足以表达"谁最后拿着"（押金条在多人手里传、钥匙移交），所以它由 lint 记为"定义在使用处"；除非第二次声明，不带进库。

## INFERRED

- **为什么是三层而不是两层**（推的）：若没有库，故事物性只有两个去处——写进引擎（引擎就认识了故事）或写进种子（种子就开始写逻辑）。库是唯一能同时保持"引擎故事无关"和"种子只写事实"的位置。
- **重放、检查点、打包是同一证据链的三个断面**（推的）：它们分别回答"状态怎么变成现在这样""中途能不能接着跑""这一次运行留下了什么"；三者都以事件账为准，所以它们的契约应当一起读，而不是各自成章。
